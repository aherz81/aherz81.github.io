TexShader

Preface

TexShader is a dll which exports two interfaces to both, the server application (your executable) and the script describing a shader. A shader is a description how to blend together/utilize different textures using functionality exposed by your 3d hardware. Actually, they 'only' set the 3d hardware into a certain state.

Generally, Shaders tend to be quite complex and only useable for special (blending) purposes. But hardcoded shaders limit the gfx designers and modellers. Therefore, shaders are scripted mostly. Parsing the scipts at runtime is obviously no option as this would leed to undesireable slow results. Especially if your shaders exceed a certain degree of complexity. On the otherhand, makeing your scripts simply and easy to parse will lead to inflexible scripts.

Luckily, OpenGL offers display lists. Stupidly, most calls (especially those to extentions) are not recorded. So The script's virtual machine supports it's own record mechnaism called execute buffers. These record all calls to native (wintel32) functions.  Using these kinda lists we can 'record' hardware state changes. So at load time of our shader we execute the (compareably slow) script once and record everything. Later on, when we want to activate a certain shader we simply playback the previously recorded shader.

Back to TexShader.dll. TexShader utilizes the ScriptEdit IDE to perform the actions required by a shader.

Within the Execute function you specify what the shader is ought to do. The NumTpu argument tells you howmany texture units are supported by the hardware.

You can create conditional shaders. This means that you can check within the Execute function if a specific hardware feature or an opengl extention is available and proceed depending in that. The script language supports any conditional standart c keyword apart from 'switch'. You can create completely different blending modes depending on your 3d hardware or what ever you like. This way any hardware feature available can be supported optimally.

A shader can be cloned by the way. That means you can use a once loaded shader as base for another one. The cloned shader will perform the same blending operations as the original did but using other textures.
