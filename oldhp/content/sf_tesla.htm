TESLA, WTF??!

You probably came here asking WTF is TESLA? And rightfully so. The amount of condensed information that can be shown on sourceforge.net is fairly limited. So this page is supposed to tell you what the TESLA project is all about.

Many years ago I wrote an extremely ugly interpreter for a simple script language for the game (about 1996, see "Old Projects->Ethos" in the projects window if you care) I was working on back then. As I was interested in the inner workings of a compiler and dissatified with what I had I started to move the rudimental parsing from the interpreter into a small compiler. This culminated into ScriptEdit which has been sort of maintained and updated until quite recently. Still, the code base originated from that old interpreter and was so ugly you wouldn't beleave it. Therefore I started a complete rewrite of the compiler/virtual machine that would utilize my new libraries and my object exchange system. While rewriting the parser I started to play around with new language features which I felt were missing from the current C++ standard. As it turned out, quite some of the ideas I had are reflected in the D language which imho is very nice and hopefully superseeds C++ one day.
So, TESLA is the feature enhanced, completely refactored, modularized and hopefully easy to use for others compiler reborn out of the old projects.

What is TESLA?

In order to apreciate what that actrually means I'll have to give you some more details. So an incomplete list of features of the compiler and its framework might help:

- TESLA is based on a small set of base libraries I wrote myself. These libraries are (obviously) no where as good, complete or bug free as boost or anything the like but they should easily coexist with such libs.
- Using my libraries the compiler, the virtual machine and all other code comes neatly encapsulated into modules that utilize a standardised communication protocol with a small interface server fully contained inside my libraries. Think of it as s light weight and portable version of COM (Common Object Model).
- TESLA is supposed to be multi platform. The linux support has not been implemented completely yet.
- TESLA compiles enhanced C++ similar code into prepriotory byte code which's syntax is similar to x86 assembly to be interpreted by a Virtual Machine which is part of the TESLA project.
- The TESLA VM allows for extensive debugging communication (e.g.: call stack, breakpoints, register watch, variable watch, ...)

So in terms of end user experience, TESLA is pretty much like Java, just a lot smaller and simpler as well as completely open source

What is TESLA not?

In order for you to decide if TESLA is for you, you need to know how TESLA compares to similar solutions.
- In order to have most of the possible fun creating TESLA and to learn the most pretty much everything contained inside TESLA is self made.
On the one hand this means that TESLA is very self contained, small and A LOT easier to understand than most compareable technology out there.
On the other hand this means:

- TESLA is prepriotory
- TESLA uses non standard algorithms which are not necessarily optimal

Into a nut shell

If you are looking for a light weight, easy to understand, portable, easy to modify and experiment with object oriented script environment then TESLA is for you.

Compiler/Language Features

Next to plain object oriented C++ the compiler supports the following enhanced meta programming features:

- very flexible templates: template arguments can be pretty much anything (e.g.: a function body) and template arguments can be used as pretty much anything
- meta programming ("pre processor") language constructs executed at compile time like if/for/while/...
- meta programming keywords that allow acces to compile time information like enumerate class members, enumerate function arguments, stringify anything,... Pretty much anything contained in the symbol table can be queried
- TAG mechnism, which allows to access the meta programming keywords as well as user defined TAGs

Example Code

                    
                    
    tag tSerialze;  //user defined TAG
    
        
    template< func_ret,func_body >
    class   cMyClass
    {
        int mInt{tSerialze="true"};         //applys the TAG tSerialze to mInt with the value "true"
        float mFloat{tSerialze="false"};
        
        func_ret MyFunc(int i) func_body;   //defines a function with templated body and return type
    };
    
    template< base >
    class   cSerializer:base
    {
        void Serialize()
        {
            //keywords starting with # are evaluated at compile time
            #for(i,base~member_count)           //access compiler defined TAG member_count which 
                                                //contains the number of members inside base
            {
                #if(base~member[i]~tSerialze)   //access TAG of the ith member of base
                {
                    //serialize base~member[i]
                    printf("serialze '%s'",toString(base~member[i]));   //toString evaluates the expression 
                                                                        //inside the brakets and returns a string   
                }
            }
        }
    };
    
    int main()
    {
        cSerializer< cMyClass< int,{return 0;} > >  object;
        
        object.MyFunc(10);
        object.Serialize();     //outputs "serialize 'mInt'"
    }
