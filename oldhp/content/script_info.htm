ASM CODE specs

Below the notepad window a wordpad window will open showing the binary code retranslated into asm.
NOTE:compiler version 5.0.0.1 has been releases with a new binary format supporting debug and runtime info.. check out the update here or download the complete binaries here. I commented this file pretty much...you can save a lot of time by reading the comments..
rather than reading all this..

You can ignore the first line of the asm code..it only indicates where the link section starts.
The first lines of code (until the first 'ret') initialize global vars. They is called at startup.
Afterwards there follows the code of each function compiled(normally in the same order as
they were defined in the .c file)


The asm code is quite similar to intel's code...so I'll list the differences:

There are 28 registers (the compiler does not use the stack to solve problems so far)
the first 26 of em you can adress as reg1...reg26
reg1 is used as basepointer(ebp) in functions

reg27 is called 'data' and represents the stackpointer (esp).
The stack is placed directly behind the dataseg in the memory.
Reg28 is called 'vip' and is the instruction pointer (eip). You should not modify it directly.
It is automatically updated by jump and return instructions and will behave
unpredictable when set directly...it's thought to be read out for debug purposes
only.

At the moment the compiler cannot solve problems which exceed the 25 available registers.
All these 25 regs are general purpose, there are no restrictions.

The data segment starts at the logical adress 0x0.
So by writing into 0x0(mov [const 0],const 0 you will access the first defined global var rather than crash things like in true c.(Don't do that in the c source!!)

Another speciality is that you have to put the 'const' prefix before any number in asm.

All datatypes have a width of at least 32bit, there is no reason to use statements like
'dword ptr' when accessing a reg or the mem.

Like in intel asm you cannot do 2 mem accesses in one command.
Every line of asm code is prefixed by a number.
This number indicates the binary offset of the command written behind it.

Probably there are some bugs in the compiler and the asm output could be more optimized.. but hey..it works :)
